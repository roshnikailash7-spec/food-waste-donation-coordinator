DSA Project • Architectural Specification

Comprehensive reference of all 8 custom data structures, time complexities, and design rationale.

1

Min-Heap (Priority Queue)

File: dsa/min_heap.py

Where used: Food expiry urgency ordering. Peek at most critical batch in O(1).

Complexities: Peek: O(1) • Push: O(log N) • Pop: O(log N)

Why: Surplus food is perishable; linear scan O(N) or continuous sorting O(N log N) is wasteful. Min-heap guarantees optimal real-time priority.

2

Hash Table with Chaining

File: dsa/hash_table.py

Where used: Fast O(1) lookup of Donors, NGOs, and Food batches by unique IDs.

Complexities: Average: O(1) Get / Put / Remove • Worst: O(N)

Why: Custom DJB2 hashing with separate chaining eliminates slow linear scans when querying entity properties during matching.

3

Singly Linked List

File: dsa/linked_list.py

Where used: Chronological donation activity history and audit log.

Complexities: Prepend: O(1) • Traversal: O(N) • Head Deletion: O(1)

Why: Prepending new events to head is strictly O(1) with zero array-shifting memory overhead.

4

FIFO Queue

File: dsa/queue.py

Where used: Pending pickup and driver transport dispatches.

Complexities: Enqueue: O(1) • Dequeue: O(1) • Peek: O(1)

Why: Fairness discipline: earliest scheduled pickups must be dispatched first, avoiding food sitting idle.

5

LIFO Stack

File: dsa/stack.py

Where used: Undo the last state-altering action (food entry, auto-match, pickup).

Complexities: Push: O(1) • Pop: O(1) • Peek: O(1)

Why: LIFO ordering is mathematically the exact mirror of chronological execution, enabling clean atomic rollback.

6

Graph + Dijkstra's Algorithm

File: dsa/graph.py

Where used: Finding closest eligible NGO to donor along city road network.

Complexities: Dijkstra: O((V + E) log V) with Min-Heap priority queue.

Why: Physical road distances dictate transit time and delivery freshness. Adjacency list is space-optimal (O(V+E)).

7

Merge Sort

File: dsa/merge_sort.py

Where used: Multi-attribute inventory ordering (by expiry or batch quantity).

Complexities: Guaranteed O(N log N) worst-case • Stable

Why: Unlike Quicksort (O(N^2) worst case), Merge Sort never degrades and preserves relative FIFO order for identical keys.

8

Binary Search

File: dsa/binary_search.py

Where used: Searching sorted inventory by quantity (exact, range, closest NGO fit).

Complexities: O(log N) comparisons vs O(N) linear scan.

Why: Logarithmic search allows instant matching against NGO capacity requests without iterating every item.
